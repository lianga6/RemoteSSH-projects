# Workspace Agent Conventions

- **Default Remote Project & Automatic Mount**:
  - **Default Target**: `lxl@10.102.137.137:/home/lxl/workspace/task_combination` → local mount point `E:/projects/RemoteSSH-projects/task_combination`.
  - **Auto-Mount Requirement**: Whenever interacting in this workspace, if the project directory is not mounted (e.g. after system, IDE, or server restarts), the agent MUST automatically check and mount it via SSHFS-Win (`& "C:\Program Files\SSHFS-Win\bin\sshfs.exe" -f lxl@10.102.137.137:/home/lxl/workspace/task_combination "E:/projects/RemoteSSH-projects/task_combination" -o ssh_command="/usr/bin/ssh" -o reconnect -o ServerAliveInterval=15 -o ServerAliveCountMax=3 -o uid=-1,gid=-1`) as a background daemon before proceeding.
- **Default Git Scope**: When working in this workspace, any general request to run `git` (status, commit, push, diff, etc.) refers to the **currently mounted remote project** (executed via SSH in `<remote_workspace>/<project_name>`), **NOT** this `RemoteSSH-projects` hub repository—unless the user explicitly says to operate on this remote-connection hub project itself.
- **Mount Isolation**: Mounted remote project folders inside this directory are ignored by `.gitignore` and must never be committed to `RemoteSSH-projects`.
- **Demo Video Links**: Whenever an evaluation, replay, or diagnostic generates demo/rollout videos (e.g., `primary.mp4`), always include clickable `file://` links to those videos in the response.
- **Toggleable Codex Delegation & Gemini Review**:
  - **User-Controlled Toggle**: Autonomous Codex delegation is controlled by [`.agents/codex-delegation.json`](.agents/codex-delegation.json) (`"enabled": true | false`, default `false`) and can also be toggled in chat at any time (e.g., `"开启自主调用 codex"` / `"关闭自主调用 codex"`).
  - **When Enabled (`"enabled": true` or explicitly requested)**: Whenever a task involves multi-file code generation, large refactoring, unit/integration test authoring & debugging, batch edits, boilerplate generation, or complex bug fixing, the agent MUST automatically activate `codex-subagent-executor` (`.agents/skills/codex-subagent-executor/SKILL.md`) and delegate implementation to remote Codex CLI via `run_codex.ps1` (`-SshTarget` using the active SSH target, `-Model gpt-6.1-sol`, `-ReasoningEffort medium`) with a compressed `Goal / Scope / Constraints / Verification` prompt. Handle trivial 1–few-line edits, read-only exploration, architecture design, and git/ops directly in Gemini.
  - **When Disabled (`"enabled": false`)**: Gemini handles all tasks directly without invoking Codex, unless the user explicitly asks to use Codex for a specific task.
  - **Review, Acceptance & Optimization**: Whenever Codex is invoked, Gemini MUST review `git status` and `git diff` (without re-reading untouched full files), verify acceptance tests pass, and perform any needed readability/edge-case polish directly (for tiny tweaks) or via `codex exec resume <session_id>` (for larger fixes) before reporting to the user.
